\section{Discussion}
\label{sec:discussion}

\paragraph{The single architectural lesson.}
The 4-channel decomposition combined with the per-channel pydantic
schema is what makes the action space a precisely
$10^2$--$10^3$-dimensional continuous surface per directive
(weights $\in [0,3]^{|\mathcal{I}_g|}$, factionTension $\in [0,1]$,
TTLs $\in [8h, 24h]$, raid-posture clamps, allowlist-restricted
intent and target vocabularies), \emph{decoupled} from entity count.
Each channel's prompt budget is bounded by
\texttt{pickHighlights} truncation rather than by the size of the
world it observes (E2). The schemas at this boundary
($\text{environment-director} \to \text{factionTension} \in [0,1]$,
\texttt{npc-policy} $\to$ intent weights $\in [0,3]^{|\mathcal{I}_g|}$)
are simultaneously the safety mechanism and the evaluation contract
--- the same artifact that prevents downstream tool grounding from
breaking is the artifact that defines what a "schema-valid directive"
counts as for H2.

\paragraph{Implications for deployment.}
Three concrete recommendations for production agent designers follow
from this architecture:
\textbf{(i)} Always test schema validity under multi-channel coherence
stress, not single-call accuracy. Single-call JSON-mode benchmarks
under-detect the compounding failure mode where each channel is
individually valid but the joint state has drifted between their
cadences. E6 is designed to surface exactly this regime.
\textbf{(ii)} Idempotent guards are required when channels feed each
other's payloads. Our \texttt{Guardrails} layer is idempotent by
construction: clamping a clamped value is a no-op. This is what
allows the four channels to run at three different cadences without
turning every cross-channel hand-off into a re-validation hazard.
\textbf{(iii)} The sandwich-normalized RAE composite is a usable
hill-climbing target. Because the fallback and oracle endpoints are
deterministic and pinned per (seed, scenario), it cannot be gamed by
LLM regression --- an LLM that drifts toward fallback-equivalent
behavior scores at the lower anchor; one that exceeds the
hand-tuned oracle scores above $1$ rather than saturating, flagging
a result for review.

\paragraph{Cost vs.\ performance Pareto.}
Following BATS~\citep{Liu2025BATS}, we report cost as
$\alpha \cdot \text{tokens} + \beta \cdot \text{tool\_calls}$ on all
leaderboards. E2 plus the decision-token efficiency analysis
(\S\ref{app:b1}) jointly establish that, in the multi-channel
orchestration regime we study, prompt-token cost grows sub-linearly
with entity count and completion-token cost is not rank-equivalent
to RAE --- i.e., the cheapest channel-routed configuration is not
trivially the best, so the architectural choice in E1 cannot be
explained away as "the hierarchical arm just spent more tokens."
