\section{Reproducibility}
\label{sec:reproducibility}

We follow~\citet{Siddiq2025SoftwareReproducibility}'s Reproducibility
Maturity Model (RMM) and target Tier 4+ across all seven smell
categories.

\subsection{Three-Tier Reproducibility Model}

Project-Utopia distinguishes three levels of reproducibility,
following~\citet{Yuan2025LayerCast}:

\begin{description}[leftmargin=*]
\item[\textbf{Tier 1 — Fallback bit-identical.}]
Runs in deterministic fallback mode (no LLM in the loop)
produce \emph{bit-identical SHA-256 hashes} across multiple
runs of the same seed and scenario. We verify this at three
sub-tiers:
60 ticks (hash \texttt{e360b76\ldots}, $\sim$1\,s wall),
1\,800 ticks (\texttt{473d1b9\ldots}, $\sim$30\,s wall), and
7\,200 ticks (\texttt{c2d86a6\ldots}, $\sim$2\,m wall).
Re-running \verb|npm run audit:determinism| in our
released container reproduces all three hashes.
We additionally provide two independent implementations
(Node.js core and Python SDK), each with its own
deterministic state hash; the Python Tier-1 hash is
\texttt{e006ea96\ldots} (30 ticks @ seed \texttt{0xC0FFEE},
scenario \texttt{temperate\_plains}). Cross-language
bit-identical reproduction is \emph{not} a goal --- the
two implementations use different RNG backends (mulberry32
vs.\ PCG64) --- but within-each-language bit-identical
reproduction is guaranteed (the \textbf{Tier 1$'$ contract}).
\item[\textbf{Tier 2 — LLM-on bit-identical via LayerCast.}]
With LayerCast~\citep{Yuan2025LayerCast} inference (16-bit
weights, FP32 compute, \texttt{deterministic: true}), the same
seed plus the same model snapshot produces bit-identical
hashes across hardware. We provide a
\texttt{LayerCastAdapter} that injects the required
\texttt{X-LayerCast-Weights / Compute / Deterministic} headers and
\texttt{inference\_config} body block. Falls back to
RecordReplayCache (Tier 2 stationary) when the upstream
proxy does not advertise LayerCast support.
\item[\textbf{Tier 3 — Production-LLM stationary.}]
With temperature $= 0$ and pinned model snapshot ID, the
\emph{distribution} of directives is statistically stationary
(KL divergence $< 0.05$ across same-prompt repetitions); raw
hashes need not match. This is the realistic ceiling for
production LLM APIs without LayerCast.
\end{description}

\subsection{Quick-Start Reproducibility}

Reviewers can verify our Tier-1 reproducibility claim through
either implementation. \textbf{Option A (Node.js)}:

\begin{lstlisting}[caption={Node.js verification},language=bash]
git clone [ANONYMIZED-REPO-URL]    # de-anonymized post-review
cd Project-Utopia
git checkout refactor/academic-benchmark-v0.11.0-rc3
npm test && npm run audit:determinism
\end{lstlisting}

\noindent\textbf{Option B (Python SDK)}:

\begin{lstlisting}[caption={Python verification},language=bash]
pip install project-utopia
project-utopia-rng-audit
project-utopia-determinism --tier 1
project-utopia run --experiment E1 \
  --scenarios temperate_plains --seeds 0xC0FFEE \
  --duration-sec 30 --out /tmp/E1.ndjson
\end{lstlisting}

\noindent
Option A runs the full 795-test suite ($\sim$\,38\,s) and the
Tier-1 60-tick determinism check ($\sim$\,2\,s); Option B runs
the 619-test pytest suite ($\sim$\,3.2\,s) and the Python
Tier-1 30-tick determinism check. Both are gated to PASS.
For Tier 3 (7\,200-tick) verification, append \texttt{--tier 3}
to the Node.js audit command (3-min wall-time).

\subsection{Anti-Contamination Safeguards}

Following PeerBench~\citep{Cheng2025PeerBench}, we deliberately
avoid agent-as-judge for capability evaluation; all metrics
are simulator-objective (DevIndex, deaths, sim-tick survival).
Three additional safeguards reduce the risk that Project-Utopia
ends up in pre-training corpora:
(1) procedurally generated maps per seed --- there is no fixed
"target answer" to memorize;
(2) structured JSON action space --- LLMs cannot game the
benchmark by producing free text that happens to match a known
answer;
(3) multi-tick trajectory required --- a single output cannot
"win" the benchmark; the LLM must emit a sequence of valid
directives over hundreds to thousands of ticks.

\subsection{Released Artifacts}

Our release contains the following artifacts, all under
\texttt{Apache 2.0 / MIT}:

\begin{itemize}[leftmargin=*]
\item \texttt{src/} --- $\sim$\,55\,k LOC simulation core, 4 LLM
channels, AgentAdapter contract (Node.js, zero npm dependencies
for the test runner).
\item \texttt{src/benchmark/} --- SimHarness, 5 dimension plugins,
ScoringEngine, DimensionNormalizer, PVB tracker, MultiBackendAdapter.
\item \texttt{src/data/prompts/} --- the 4 verbatim system prompts
defining the LLM contract surface; this \emph{is} the action-space
specification.
\item \texttt{tools/audit/} --- determinism-check (3 tiers) +
RNG-coverage report.
\item \texttt{server/} --- \texttt{ai-proxy.js} (OpenAI-compatible)
and \texttt{agent-bridge.js} (cross-vendor 9-cell routing).
\item \texttt{scripts/benchmark-paper.mjs} --- one-line CLI to
reproduce any Project-Utopia experiment.
\item \texttt{output/determinism-tier3-temperate\_plains.json} ---
the full Tier-3 hash manifest verifying our claim.
\item \texttt{docs/ai-research/} --- $\sim$\,3\,800 LOC of
research-method documentation including this paper's source.
\item \texttt{metadata/croissant.json} --- Croissant 1.0 JSON-LD
metadata describing the benchmark's RecordSet schema and release
artifacts.
\end{itemize}

\subsection{Bilingual Implementation Rationale}

Project-Utopia ships with two independent implementations
because the audience for an LLM benchmark spans two disjoint
communities. Node.js is the canonical language for
HTTP-proxy-heavy agent orchestration (the LLM proxy, schema
validation, agent-bridge); Python is the canonical language
for ML researcher tooling (pandas post-processing, scipy
statistical inference, matplotlib figures). Rather than force
one community to learn the other, both implementations share
the verbatim 4-channel prompts (the LLM contract surface) and
the same scenario blueprints. Reviewers may verify our
reproducibility claim through either implementation --- the
Python \texttt{project-utopia} PyPI package is a self-contained
$\sim$\,5\,500 LOC re-implementation (619 tests passing,
$\sim$\,3.2\,s wall) that has shed game-flavor code retained in
the Node.js build.
