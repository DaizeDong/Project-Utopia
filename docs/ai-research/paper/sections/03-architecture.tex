\section{Project-Utopia Architecture}
\label{sec:architecture}

\subsection{Overview: A Tool-Grounded 4-Channel Action Surface}

Project-Utopia exposes a 4-channel LLM action surface above a fixed,
queryable tool layer. The agent has \emph{no syscall-level tool
choice}: it emits structured directives, and the tool layer
deterministically grounds them to per-entity actions via fixed tool
implementations. This is the language convention of
ReAct~\citep{Yao2023ReAct} and Toolformer~\citep{Schick2023Toolformer}
extended to a multi-channel setting: each channel binds to one tool,
and the schema is the agent--tool interface contract.

The tool layer offers four deterministic, queryable implementations
that LLM channels indirectly invoke through directives:
\textbf{(T1) path query tool} — A* over a versioned grid, cached by
$(\text{faction}, \text{gridVersion}, \text{costVersion})$;
\textbf{(T2) group steering tool} — Boids with per-group profiles
applying \texttt{intentWeights} to NPC steering;
\textbf{(T3) FSM intent application tool} — per-NPC finite-state
machine driven by \texttt{POLICY\_INTENT\_TO\_STATE} mapping;
\textbf{(T4) build planner tool} — PlanExecutor over BuildSystem,
grounding multi-step plans tile-by-tile.
A seeded RNG and a fixed system order tie these tools into a
reproducible per-tick pipeline.

Concretely, the per-tick pipeline runs at $\Delta t = 1/30$\,s through
17 systems (perception $\rightarrow$ LLM gates $\rightarrow$ policy
applier $\rightarrow$ FSM $\rightarrow$ A* $\rightarrow$ Boids
$\rightarrow$ integration $\rightarrow$ telemetry). The simulation
hosts 20--50 NPC workers harvesting resources, building, and
defending against periodic raids over 60--240 sim seconds
(configurable up to 24 hours). The LLM is consulted at three nested
cadences: strategic every 90\,s, environment / npc-policy every
5--15\,s, colony-agent on event triggers.

Crucially, \emph{the LLM never controls individual entities}. It
produces low-rank, schema-validated, clamped \emph{directives} that
flow through the deterministic tool layer: a 4-channel directive
stream $\to$ group policy applier (T3) $\to$ per-NPC FSM
$\to$ A* target (T1) $\to$ Boids \texttt{desiredVel} (T2)
$\to$ integrated position. This handoff is the deterministic
boundary that makes bit-identical reproducibility possible at every
channel even when the LLM itself is non-deterministic
(see \S\ref{sec:reproducibility}).

\subsection{The Four LLM Decision Channels}
\label{sec:channels}

\paragraph{Environment-director} (\emph{cadence}: 5--15\,s, throttled by
\texttt{tuning.environmentDecisionIntervalSec}). Emits directives
--- weather (enum), \texttt{durationSec} (clamped 8--180\,s),
\texttt{factionTension} ($\in$ [0, 1]), \texttt{eventSpawns} (at most
3, each with intensity $\geq$ 0.4 and clamped duration) --- that the
\emph{event scheduler tool} grounds into naturalistic stressors
(droughts, storms, faction buildups). Functions as the environmental
state-perturbation tool to which the policy channel must adapt.

\paragraph{NPC-policy} (\emph{cadence}: 5--15\,s, additionally
gated by threat $\leq 14$ tiles, guard deficit, or active worker
strikes). Emits per-group policy directives
$\{\text{groupId}, \text{intentWeights} \in [0,3]^{\sim 10},
\text{riskTolerance} \in [0,1], \text{targetPriorities} \in [0,3]^{|\mathcal{T}|},
\text{ttlSec} \in [8, 24\,\text{h}]\}$
that the \emph{group steering (T2) + FSM intent applier (T3) tools}
then ground: intent weights flow through
\texttt{POLICY\_INTENT\_TO\_STATE} into per-NPC FSM state
preferences, while target priorities are interpreted by the A* path
query tool (T1).

\paragraph{Strategic-plan} (\emph{cadence}: 90\,s heartbeat plus
crisis triggers --- workers $\to 0$, food/wood $\leq 5$, threat $\geq 85$
--- with 15\,s cooldown). Emits free-text colony-level objectives
plus structured \texttt{primaryGoal} / \texttt{constraints} /
\texttt{resourceBudget} directives that the \emph{plan-arbitration
tool} grounds by adjusting downstream channel budgets. Strategic
plans are advisory; lower channels can override under raid posture
clamps.

\paragraph{Colony-agent} (\emph{cadence}: sim-time gated, additionally
triggered by plan stalls). Emits multi-step plan directives
$[(\text{action}, \text{args}, \text{depends\_on})]$ that the
\emph{build planner tool (T4)} (\texttt{PlanExecutor} over
\texttt{BuildSystem}) grounds tile-by-tile. Wraps a Perceive $\to$
Plan $\to$ Ground $\to$ Execute $\to$ Evaluate $\to$ Reflect
loop~\citep{Yao2023ReAct, Shinn2023Reflexion}, where Ground is the
tool-invocation step.

\subsection{Schema Validation and Guardrails: the Agent$\leftrightarrow$Tool Contract}

Schemas and guardrails are not safety bolt-ons; they \emph{are} the
agent--tool interface contract --- the same role as the typed JSON
signatures of ToolLLM~\citep{Qin2024ToolLLM} and the function-call
schemas of Gorilla~\citep{Patil2023Gorilla}, generalized to four
parallel channels. All four channels share two filters before
directives reach the tool layer.
\textbf{ResponseSchema} performs JSON-Schema validation: unknown enum
values are dropped, NaN values are rejected, field types are coerced.
\textbf{Guardrails} clamps numeric ranges ($\text{weights} \in [0,3]$,
$\text{risk} \in [0,1]$, TTL $\in$ [8\,h, 24\,h]) and applies
\emph{raid-posture clamps}: when threat is imminent, intent weights
for combat-relevant intents are forcibly raised regardless of LLM
output. This contract makes the action space precisely
$\sim$\,10$^2$--10$^3$ continuous axes per directive, decoupled from
entity count, and it ensures the tool layer never enters an invalid
state even when the LLM emits adversarial or malformed JSON.

\subsection{Determinism and the AgentAdapter Seam}
\label{sec:adapter-seam}

The tool layer is deterministic given a seed. RNG flows through
\texttt{project\_utopia.app.rng}; A* paths are cached by
$(\text{faction}, \text{gridVersion}, \text{costVersion})$;
Boids accumulators run in fixed order; \texttt{PathWorkerPool} is
disabled in \texttt{deterministic=True} mode. Verifying determinism
empirically is non-trivial: we built
\texttt{project\_utopia.tools.audit.determinism\_check} which runs
the harness twice with the same seed and compares SHA-256 hashes
of slim state snapshots. Three tiers are gated: 30 ticks,
1\,800 ticks, and 7\,200 ticks (240 sim-seconds). All three pass
with bit-identical hashes (\texttt{e006ea96\ldots},
\texttt{e99d4fcb\ldots}, \texttt{87ecd82b\ldots};
see Appendix~\ref{app:determinism-report}).

The \textbf{AgentAdapter} is the interface that any LLM (or
fallback policy, or scripted oracle) must implement to drive
the four channels:

\begin{lstlisting}[language=Python, caption={AgentAdapter contract}]
async def request(self, channel: str, payload: Any,
                  options: dict | None = None) -> DecisionResponse:
    # channel in {environment-director, npc-policy,
    #             strategic-plan, colony-agent}
    # returns DecisionResponse(data, fallback, usage,
    #                          latency_ms, model, error, debug)
    # MUST NOT raise; on failure return a fallback DecisionResponse
    ...
\end{lstlisting}

Concrete adapters in our suite include:
(1) \texttt{LLMClient} (OpenAI-compatible HTTP via litellm);
(2) \texttt{NoopAgentAdapter} / \texttt{ScriptedOraclePolicy} (used for
the sandwich-norm fallback and oracle terms);
(3) \texttt{HTTPAgentClient} dispatching to a 9-cell cross-vendor
routing config (\texttt{project\_utopia.cli.agent\_routing});
(4) \texttt{LayerCastAdapter} wrapping any inner adapter with
deterministic-inference headers;
(5) \texttt{RecordReplayCache} (VCR-cassette-style) for offline
re-execution from a previous run's transcript.

\texttt{AdapterToLLMClient} bridges any \texttt{AgentAdapter} into the
existing simulation systems by exposing the four legacy method
signatures (\texttt{request\_environment}, \texttt{request\_policies},
\texttt{request\_strategic}, \texttt{request\_plan}) that the existing
strategic / environment / brain / colony-director systems call.
This single seam is what makes E3's 9-cell cross-vendor matrix possible
without modifying any simulation system.
