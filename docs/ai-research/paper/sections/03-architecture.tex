\section{Project-Utopia Architecture}
\label{sec:architecture}

\subsection{Overview: A Tool-Grounded 4-Channel Action Surface}

Project-Utopia exposes a 4-channel LLM action surface above a fixed, queryable tool layer. The agent has \emph{no syscall-level tool choice}: each channel binds to one tool, and the schema is the agent--tool interface contract. This is the language convention of ReAct~\citep{Yao2023ReAct} and Toolformer~\citep{Schick2023Toolformer} extended to a multi-channel setting; the LLM emits structured directives and the tool layer deterministically grounds them to per-entity actions through fixed implementations.

The tool layer offers four deterministic implementations that LLM channels indirectly invoke through directives: \textbf{(T1) path query tool} --- A* over a versioned grid, cached by $(\text{faction}, \text{gridVersion}, \text{costVersion})$; \textbf{(T2) group steering tool} --- Boids with per-group profiles applying \texttt{intentWeights} to NPC steering; \textbf{(T3) FSM intent application tool} --- per-NPC finite-state machine driven by \texttt{POLICY\_INTENT\_TO\_STATE} mapping; \textbf{(T4) build planner tool} --- PlanExecutor over BuildSystem, grounding multi-step plans tile-by-tile. A seeded RNG and a fixed system order tie these into a reproducible per-tick pipeline at $\Delta t = 1/30$\,s through 13 ordered systems (perception $\to$ LLM gates $\to$ policy applier $\to$ FSM $\to$ A* $\to$ Boids $\to$ integration $\to$ telemetry).

Crucially, \emph{the LLM never controls individual entities}. It produces low-rank, schema-validated, clamped directives that flow through the deterministic tool layer: 4-channel directive stream $\to$ group policy applier (T3) $\to$ per-NPC FSM $\to$ A* target (T1) $\to$ Boids \texttt{desiredVel} (T2) $\to$ integrated position. This handoff is the deterministic boundary that makes bit-identical reproducibility possible (\S\ref{sec:reproducibility}).

\subsection{The Four LLM Decision Channels}
\label{sec:channels}

\paragraph{Environment-director.} \emph{Cadence}: 5--15\,s, throttled by \texttt{tuning.environmentDecisionIntervalSec}. \emph{Schema}: \{weather: enum \texttt{clear|rain|storm}, \texttt{durationSec} $\in$ [8, 180], \texttt{factionTension} $\in$ [0, 1], \texttt{eventSpawns}: $\leq$3 with intensity $\geq$ 0.4\}. The event scheduler tool grounds these directives into naturalistic stressors. This is the state-perturbation channel to which the policy channel must adapt, matching the ReAct~\citep{Yao2023ReAct} observe$\to$act pattern at a coarser cadence.

\paragraph{NPC-policy.} \emph{Cadence}: 5--15\,s, additionally gated by threat $\leq 14$ tiles, guard deficit, or active worker strikes. \emph{Schema}: $\{\text{groupId}, \text{intentWeights} \in [0,3]^{|\mathcal{I}_g|}, \text{riskTolerance} \in [0,1], \text{targetPriorities} \in [0,3]^{|\mathcal{T}_g|}, \text{ttlSec} \in [8, 24\,\text{h}]\}$. Intent weights flow through \texttt{POLICY\_INTENT\_TO\_STATE} into per-NPC FSM state preferences (T3); target priorities are interpreted by A* (T1); group steering (T2) consumes the resulting \texttt{intentWeights}. The typed directive surface mirrors the function-signature pattern of Toolformer~\citep{Schick2023Toolformer} extended to a parallel-channel cadence.

\paragraph{Strategic-plan.} \emph{Cadence}: 90\,s heartbeat plus crisis triggers (workers $\to 0$, food/wood $\leq 5$, threat $\geq 85$) with 15\,s cooldown. \emph{Schema}: \{\texttt{primaryGoal}: str, \texttt{constraints}: str[], \texttt{resourceBudget}: \{food, wood, stone\}\}. The plan-arbitration tool grounds directives by adjusting downstream channel budgets. Strategic plans are advisory; lower channels override under raid-posture clamps.

\paragraph{Colony-agent.} \emph{Cadence}: sim-time gated, additionally triggered by plan stalls. \emph{Schema}: $[(\text{action: enum}, \text{args: obj}, \text{depends\_on: int[]})]$ multi-step plan directives that the build planner tool (T4, \texttt{PlanExecutor} over \texttt{BuildSystem}) grounds tile-by-tile. Wraps a Perceive $\to$ Plan $\to$ Ground $\to$ Execute $\to$ Evaluate $\to$ Reflect loop~\citep{Yao2023ReAct, Shinn2023Reflexion}, where Ground is the tool-invocation step.

\subsection{Schema Validation and Guardrails: the Agent$\leftrightarrow$Tool Contract}
\label{sec:contract}

Schemas and guardrails are not safety bolt-ons; they \emph{are} the agent--tool interface contract. \textbf{Schema + Guardrails is contribution C1.} All four channels share two filters before directives reach the tool layer. \textbf{ResponseSchema} performs JSON-Schema validation: unknown enum values are dropped, NaN values rejected, field types coerced. \textbf{Guardrails} clamps numeric ranges ($\text{weights} \in [0,3]$, $\text{risk} \in [0,1]$, TTL $\in$ [8\,h, 24\,h]) and applies the \emph{raid-posture clamp}: when threat $\geq 80$, intent weights for combat-relevant intents are forcibly raised regardless of LLM output. The guard is an \textbf{idempotent fixed point}: \texttt{guard(guard(x)) == guard(x)} for every directive shape.

This is the typed-function-signature pattern of ToolLLM~\citep{Qin2024ToolLLM} and Gorilla~\citep{Patil2023Gorilla} generalized to four parallel channels with idempotent guards. Single-channel selection benchmarks don't need idempotency because their guard scope is one call; orchestration of $N$ parallel channels requires it because un-clamped output from one channel may re-enter another channel's prompt payload on the next tick, and a non-idempotent guard would compound rather than stabilize. The contract makes the action space $\sim$\,10$^2$--10$^3$ continuous axes per directive, decoupled from entity count, and ensures the tool layer never enters an invalid state under adversarial or malformed JSON.

\subsection{Determinism and the AgentAdapter Seam}
\label{sec:adapter-seam}

The tool layer is deterministic given a seed. RNG flows through \texttt{project\_utopia.app.rng}; A* paths are cached by $(\text{faction}, \text{gridVersion}, \text{costVersion})$; Boids accumulators run in fixed order; \texttt{PathWorkerPool} is disabled in \texttt{deterministic=True} mode. \texttt{project\_utopia.tools.audit.determinism\_check} runs the harness twice with the same seed and compares SHA-256 hashes of slim state snapshots. Three tiers pass with bit-identical hashes: 30 ticks \texttt{be19781c\ldots}, 1\,800 ticks \texttt{f7a099a4\ldots}, 7\,200 ticks \texttt{43cb6aec\ldots} (Appendix~\ref{app:determinism-report}).

The \textbf{AgentAdapter} is the interface that any policy (LLM, fallback, or scripted oracle) must implement to drive the four channels:

\begin{lstlisting}[language=Python, caption={AgentAdapter contract}]
async def request(self, channel: str, payload: Any,
                  options: dict | None = None) -> DecisionResponse:
    # channel in {environment-director, npc-policy,
    #             strategic-plan, colony-agent}
    # MUST NOT raise; on failure return a fallback DecisionResponse
    ...
\end{lstlisting}

Concrete adapters in the core suite: (1) \texttt{NoopAgentAdapter} --- schema-valid no-op for the sandwich-norm lower bound; (2) \texttt{LLMClient} --- OpenAI-compatible HTTP via litellm; (3) \texttt{FlatBaselineAdapter} --- the E1 single-channel control that emits per-worker FSM-state preferences directly; (4) \texttt{ScriptedOraclePolicy} --- hand-coded heuristic upper bound for the sandwich norm. Tier-2 deterministic-inference adapters and cassette replay are documented in \S\ref{sec:reproducibility}.
