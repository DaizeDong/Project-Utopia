\section{Limitations and Future Work}
\label{sec:limitations}

\paragraph{Limitations.}
(1) \textbf{Domain.} Project-Utopia is a colony simulation in a
2-D tile world. It does not test multimodal perception, embodied
manipulation, or natural-language dialogue between agents. Domain
generalization to other fixed-tool-surface settings (city traffic,
hospital scheduling, supply-chain orchestration) is left as future
work.
(2) \textbf{Sample size.} The 3-experiment matrix uses 10 seeds per
cell for E1 and E2 and 5 seeds for E6, which is at the low end of
statistical justifiability. We adopt~\citet{Bowyer2025DontUseClt}'s
Beta-Binomial methodology and pair it with PVB variance reduction
(\S\ref{sec:metrics}), but acknowledge that doubling seed count
would tighten credible intervals and may reveal effects below our
current detection threshold.
(3) \textbf{LLM API stationarity.} Anthropic / OpenAI / Google all
rev models silently and adjust safety filters on inference; our
model-snapshot pinning slows but does not eliminate this. The
RecordReplayCache lets reviewers replay our exact prompts-and-responses
transcript bit-identically, but re-running with the latest production
endpoint is not guaranteed to reproduce.
(4) \textbf{Partial observability.} Project-Utopia exposes the full
world summary to all four channels. A more realistic deployment
would give each channel only its proper observation slice. We
support this via a \texttt{VisibilitySystem} but have not yet wired
it into the experimental matrix; this is the most important deferred
ablation.
(5) \textbf{Multi-LLM negotiation.} Channels communicate only through
state mutation, not through inter-LLM text traffic. This is out of
scope for the orchestration regime we test: H1 and H2 specifically
ask what happens when four parallel channels of a single agent
orchestrate a fixed tool surface, not what happens when multiple
agents negotiate. Concordia~\citep{Vezhnevets2023Concordia}'s
Game-Master-as-broker pattern would be a natural extension but is
deliberately not exercised here.
(6) \textbf{Sample-efficient learning under directive constraints.}
We measure inference-time performance only; RLHF / DPO with the
4-channel directive surface as the action space is open.
(7) \textbf{Fixed tool set.} Unlike
Toolformer~\citep{Schick2023Toolformer},
Gorilla~\citep{Patil2023Gorilla}, and
ToolLLM~\citep{Qin2024ToolLLM} --- which evaluate agents that
\emph{choose} tools from a large inventory --- Project-Utopia
evaluates agents that \emph{orchestrate a fixed 4-tool surface}.
This is intentional: it is the design choice that defines the
orchestration regime. Open-world tool discovery is out of scope by
construction; domain-transfer claims are limited to settings where
the tool surface is known a priori (industrial workflow
orchestration, robotics primitives, scripted enterprise APIs).
(8) \textbf{Empirical evidence pending.} At submission, no real-LLM
runs are populated. The pipeline is verified end-to-end on
fallback-only NDJSON: schema validity, guardrail idempotence,
bit-identical determinism (\S\ref{sec:reproducibility}), and figure
rendering all run through the released CLI. Cell-level real-LLM
signal for H1 and H2 is reserved for the camera-ready once API
access is provisioned.

\paragraph{Future work.}
Camera-ready will populate H1 and H2 with the model menu from
\S\ref{sec:exp:setup} (one frontier closed-weight, one mid-tier
closed-weight, one open-weight 7B-tier for H2; the single
Claude-Sonnet model for H1), then extend the methodology to
additional fixed-tool-surface domains where the agent--tool contract
is known a priori.

\paragraph{What we explicitly do \emph{not} promise.}
Project-Utopia does not claim to test "general intelligence,"
linguistic competence, or commonsense reasoning. It tests
\emph{multi-channel orchestration of a fixed tool surface under
schema-validated long-horizon resource pressure}. Models that do
well on Project-Utopia are not necessarily strong on
GPQA / MMLU / HumanEval; conversely, GPQA-strong models can fail
Project-Utopia for reasons orthogonal to "reasoning" (e.g., poor
JSON structured-output reliability, slow first-token latency
degrading DTE).
